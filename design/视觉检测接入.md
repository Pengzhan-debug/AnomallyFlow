# 视觉样本与自动异常检测接入

更新：2026-11-02。已实现样本登记、检测协议和业务适配；尚未训练或部署真实视觉模型。DeepSeek 负责调查报告，不负责本轮图像像素检测。

## 当前可以做什么

登录工作台的“视觉样本库”，按产品导入 JPG/PNG。工程师、主管和管理员可登记，其他角色只读。可输入新样本产品代码，在生产批次尚未建立时先整理样本；导入不会伪造生产批次，正式检测仍须关联批次。每批最多 50 张，每张不超过 20 MB。样本需人工标注正常/异常、选择训练/验证/测试集，并填写来源；当前按仅正常样本训练的异常检测基线设计，异常图像只能进入验证或测试集。

图像按租户授权，原始文件与标签记录保存。相同租户中同一文件哈希只能登记一次；换标签、产品或划分会冲突，防止相同文件进入训练与评测两边。相同工件的重复拍摄、压缩/裁剪后的近似图像仍需人工按工件、批次、拍摄时段分组，文件哈希不能解决这些泄漏。当前没有修改已登记样本或像素缺陷掩膜的界面；错误标签需由后续数据治理流程处理，暂不直接用于训练。

可导出 JSON 清单，含来源、标签、划分、尺寸、内容哈希、受保护的图像 API 路径与 `manifest_sha256`，供后续训练程序按精确样本集合取图。清单不含认证令牌、本地存储路径。导入和导出都不会自动训练模型。

## 仓库内的 Anomalib 适配服务

`detector/` 是按本文件协议实现的可选服务，基线为 Anomalib 2.7 的 PatchCore（wide_resnet50_2）。它和 API/Worker 读取同一份 `DETECTOR_PROFILES_PATH`，阈值与版本只有一份来源；产品到 checkpoint 的映射在 `detector/models/registry.json`，加载前校验文件的 SHA256。请求的模型或阈值版本与配置不一致、产品未部署或推理失败时返回 `ERROR`，由业务侧转人工，不会回退 Mock 或伪造正常结果。

`detector/train_patchcore.py` 负责训练、导出 torch checkpoint 和阈值校准；校准在独立验证集上取正常分数的 99.5% 分位和异常分数的 0.5% 分位，不可分时拒绝写入配置。checkpoint 是 pickle 格式且与 anomalib 版本绑定，训练和服务必须使用同一镜像版本，只加载本项目生成的模型。

返回的异常定位图会缩放到上传原图尺寸并编码为 8 位灰度 PNG；超过 4 MB 时省略。当前 `quality_passed` 只检查图像可解码、边长至少 32 像素且非空白，不包含拍摄质量模型。服务默认单进程，`Idempotency-Key` 缓存保存在内存；协议测试不需要 torch，见 `detector/tests`。启用步骤和命令见根目录 README。仓库不包含训练权重、真实样本指标或已验收阈值。

## 检测配置

检测模式与 `AGENT_MODE` 独立。当前 `.env` 未指定检测模式时默认 `mock`。不要用 DeepSeek 的 API URL 作为检测服务 URL。

```dotenv
DETECTOR_MODE=http
DETECTOR_URL=http://your-visual-service:8080/inspect
DETECTOR_PROFILES_PATH=data/detector_profiles.json
DETECTOR_API_KEY=
```

从 `data/detector_profiles.example.json` 创建按产品的配置。示例中的模型版本、阈值和数值仅展示格式，不能视为校准结果。每个产品必须指定 `model_version`、`threshold_version`、`normal_max`、`abnormal_min`，分数规范化至 [0,1] 且两个边界严格递增。API 和 Worker 须使用相同图像存储卷；容器中的配置文件路径必须实际存在。

任务创建时固定检测模式、服务地址与该产品配置；后续部署修改仅影响新任务。旧任务无配置快照时保留 Mock 行为。服务配置缺失返回 503，不创建一个伪装成真实检测的 Mock 任务。端点不能包含用户名、密码或查询参数；服务凭据只从 Worker 环境变量读取，不进入任务或报告。`GET /api/v1/detector` 给页面返回当前模式与产品版本，不暴露地址或密钥，`model_validated=false` 表示目前尚无模型验收登记。

## 外部服务协议

Worker 向配置的完整 URL 发送 HTTP POST multipart：

| 字段 | 含义 |
| --- | --- |
| `image` | 已校验的原图字节，JPG/PNG |
| `request_id` / `tenant_id` | 服务端任务与租户身份 |
| `product_code` / `image_sha256` | 产品及原图哈希 |
| `model_version` / `threshold_version` | 此任务固定的模型、阈值版本 |

请求头 `Idempotency-Key` 为 `task_id:model_version:threshold_version`；可选 Bearer 服务凭据。调用超时 20 秒，不跟随重定向，响应解码后上限 8 MB。外部服务必须根据请求 ID 和幂等键处理重发；本地节点已提交的结果保存在 `inspection_tasks.detection_json`，后续调查节点不会重复检测。

成功响应为严格 JSON（示例表示协议测试，数值没有质量结论）：

```json
{
  "request_id": "QI-example",
  "product_code": "VALVE-A",
  "image_sha256": "与请求完全相同的 SHA256",
  "status": "ABNORMAL",
  "anomaly_score": 0.87,
  "quality_passed": true,
  "confidence_note": "请由视觉服务给出拍摄质量和适用范围说明",
  "model_version": "与请求完全相同的模型版本",
  "threshold_version": "与请求完全相同的阈值版本",
  "inference_ms": 24.0,
  "defect_label": null,
  "anomaly_map_png_base64": null
}
```

`status` 只能是 `NORMAL/ABNORMAL/UNCERTAIN/ERROR`，分数必须有限且在 [0,1]；只有 ERROR 可无分数。质检服务不能通过状态字段绕过本地质量门：质量不合格或服务声明不确定时为 UNCERTAIN；分数在两个边界之间也为 UNCERTAIN。可信结果按固定阈值判定，明确相反的正常/异常状态会被拒绝。身份、图像哈希或版本不一致、格式错误、网络失败都进入 ERROR/NEEDS_REVIEW，不创建可审批报告、不回退到 Mock。

异常定位图可空；有图时传 base64 PNG，解码后不超过 4 MB，尺寸必须与原图一致。服务端保存后只通过任务授权的 `GET /api/v1/inspections/{id}/anomaly-map` 读取，不接受服务提供的任意远程图像 URL。前端只在确有定位图时显示入口；Mock 不生成伪造热力图。API 也提供受保护的原图读取和检测元数据。

补证暂不重跑视觉检测，保留 v1 检测结果；补证说明进入调查，图像供人工核验。后续若需要补拍图自动检测，须增加独立 finding 身份和质量门，不能覆盖旧结果。

## 进入真实自动检测的顺序

1. 选定一个产品和固定拍摄条件，导入人工确认的正常及异常图像，按工件/批次独立划分数据。没有真实样本时，可按 PRD 先做公开研究数据上的演示。
2. 在独立视觉环境验证一个正常样本训练基线。可先评估 [Anomalib 的 PatchCore](https://anomalib.readthedocs.io/en/latest/markdown/guides/reference/models/image/patchcore.html)，其用正常图像建立特征库；选择和实际性能仍需用目标类别验证。当前仓库未安装 Anomalib/PyTorch，也没有模型权重。
3. 只在验证集校准归一化和不确定区间，保存模型、阈值、预处理与清单版本；测试集保持独立。报告图像级 AUROC、误报/漏检、分产品混淆矩阵和延迟；有像素标注后再测像素级指标，未标注不能报告 Pixel AUROC。
4. 将通过评测的推理服务接入本协议，在工作台完成上传→真实检测→异常调查→人工审批。第一版自动检测指上传后自动执行；相机实时采集和生产线联动不包含在本轮接口中。

HTTP 检测结果不使用演示场景编号判定正常/异常，也不触发演示场景的故意坏引用；当前调查风险下限为 MEDIUM，模型可提高风险，补证不能降低上版风险。正式产品风险政策仍需配置与验收。

若样本与运算环境已就绪，可按约 3–5 个开发日规划单类别试用：基线 2–3 日，阈值评测和业务联调 1–2 日。该估算不包含采样、补标、硬件准备和性能不达标后的迭代，不是生产上线日期。生产试用还需先约定可接受的误报、漏检和拍摄质量门。公开研究数据的许可和下载范围以 [MVTec 官方说明](https://www.mvtec.com/research-teaching/datasets/mvtec-ad) 为准。

当前验证边界见根目录 TESTING.md。协议测试成功只表示适配行为正确，不等于检测准确率通过。
