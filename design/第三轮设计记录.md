# QualityFlow AI 2.0 第三轮设计记录

本轮继续完善 PRD V1.0 的异常路径和工单操作。所有页面仍是本地设计原型；状态切换、审批、分派和处置只改变浏览器中的演示状态，不调用真实 API。

## 关键状态和文案

**列表加载失败**：展示“任务列表加载失败”，保留任务上下文和重试方向；不能展示“暂无任务”，因为两者业务意义不同。连接中断后重新查询 API 中的正式状态。

**证据核验失败**：保留检测异常结果与分数，但报告入口不可用，说明是证据 ID、归属或版本校验失败。原报告及验证错误进入审计，等待人工检查或重新调查。

**调查预算超限**：展示调查被中止、证据可能不足和人工复核入口。不得让 UI 表现为“Agent 已完成根因确认”。

**审批队列切换**：列表项与右侧详情必须指向同一任务及报告版本。原型只为 QI-240817 提供完整报告详情；其他两条展示摘要和版本线索，完整报告入口隐藏。正式实现应为每条记录提供报告与证据跳转。

**工单处理**：WO-240806 用作分派和处置样例，WO-240809 用作复检确认样例。切换工单时详情随之切换；已关闭样例只读，当前仍未设计完整详情。

## 与实现的接口约束

- 任务列表状态来自 `GET /api/v1/inspections`，加载失败应保留 `error_code` 与 `trace_id`，不把网络错误映射成空集合。
- 审批决定带 `approval_id`、报告版本及目标状态版本。并发或旧版本冲突返回明确错误，前端重新获取最新报告。
- 分派与处置使用工单目标版本或 `If-Match`；每次成功写入追加 `work_order_events`，不能覆盖旧处理记录。
- 证据核验失败与 Agent 超预算都进入任务的人工处理分支，状态与工具日志可追溯。
- 登录页的错误状态预览只展示文案，输入内容不会发送或保存；正式实现需遵循 FR-01 的 401/403 与资源过滤要求。
